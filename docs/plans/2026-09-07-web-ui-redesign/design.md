# Переработка веб-интерфейса прошивки «Самовар» — дизайн (черновик для согласования)

Дата: 2026-09-07. Статус: **внедрено в `data_raw/` (пункты 1–7 плана), код прошивки не менялся**.
Пункт 8 (копии HTML в WordPress-плагине) не выполнялся — отдельная задача.
Прототип главного экрана: `prototype-rect.html` (открыть в браузере), скриншоты `proto-*.png`.

## Визуальный тезис
Приборная панель: тёплый нейтральный фон, один акцент — медь (как в иконке мобильных приложений),
одна тревожная краска (красный). Цифры — главное, рамки и тени — минимум. Тёмная и светлая тема
из тех же токенов. Шрифт системный (веб-шрифт не грузим с ESP32), цифры табличные
(`font-variant-numeric: tabular-nums`), чтобы значения не прыгали при обновлении раз в 2 с.

## Раскладка главного экрана режима (десктоп ≥ 1000 px)
```
┌ шапка: лого · навигация (Режим · Программа · График · Настройки · Ещё) · связь/версия/время · сообщения · тема ┐
├ полоса этапа: «Отбор тела», строка N из M, прогресс-бар, работа/осталось/отобрано/скорость                 ┤
├───────────┬──────────────────────────────┬──────────────────────┤
│ Действия  │  МНЕМОСХЕМА (SVG, живая)     │ Текущая строка про-  │
│ Датчики   │  куб · царга · дефлегматор · │ граммы: тип, ёмкость,│
│  + уставки│  ТСА · насос отбора · банки  │ прогресс, параметры, │
│           │                              │ «следующая», ссылка  │
│ Детектор  │  сервопривода · вода · нагрев│ Регулятор · Отбор ·  │
│           │                              │ Давление             │
└───────────┴──────────────────────────────┴──────────────────────┘
```
Мобильный (≤ 640 px): одна колонка — шапка, полоса этапа, мнемосхема (не выше половины экрана),
под ней строка «Ключевое» (Δ пар−царга, отклонение пара от уставки, куб и порог стопа, детектор),
затем блок «Управление» (напряжение, скорость отбора, «Зафиксировать Т тела»), карточка текущей строки,
давление. Полный список датчиков на мобильном не показываем — температуры уже есть на схеме. Кнопки процесса закреплены внизу экрана (Нагрев · Пауза · Далее · Сброс).

Полный список строк программы на главном экране не показываем: он остаётся на вкладке «Программа».
На главной — только карточка текущей строки (тип, ёмкость, прогресс, скорость, доля, напряжение, время)
и одна строка «следующая». Ссылки на вкладку не нужно — она есть в навигации.

## Мнемосхема — особенности «Самовара» (чего нет у SSVC)
- **Насос отбора** (шаговый/перистальтический) с вращающимся ротором и каплями, скорость л/ч.
- **Банки сервопривода** (до 5 позиций): активная подсвечена медью, заполнение по объёму строки.
- **Датчик уровня флегмы** на дефлегматоре (зелёный/красный).
- **ТСА** отдельной трубкой с датчиком.
- **Регулятор мощности** — спираль в кубе светится при включённом нагреве, подпись «В · Вт».
- **Давление в кубе** (MPX/XGZ) внутри куба, атмосферное — в карточке.
- **Детектор проскока примесей** — отдельный блок со статусом и трендом.
- Вода охлаждения — анимированный пунктир, направление потока.
- Пузырьки в царге только при включённом нагреве; при паузе схема «замирает» (анимации стоп).
По режимам: дистилляция — та же схема без насадки/дефлегматора (прямоточный холодильник);
БК/НБК — колонна с подачей; пиво — заторный котёл с мешалкой и насосом, шаги «затирание/кипячение»;
сыр — котёл, мешалка, pH.

## Что сохраняется (ограничения)
- **Все `id` элементов и функции `SamovarApp.*`** — на них завязаны 29 браузерных тестов и `app.js`.
  Переработка = новая разметка/CSS вокруг тех же id, не переписывание логики.
- Шаблонизатор `%PLACEHOLDER%` и партиалы `<!--#include -->`, сборка `tools/build_web_assets.py`.
- Бюджет LittleFS: раздел 1 МБ, сейчас `data/` 372 КБ. Мнемосхема — инлайн-SVG в partial'е (~6 КБ gz).
- Без внешних CDN, без фреймворков.

## Переключение старого и нового дизайна
Требование: пользователь может вернуться к прежнему интерфейсу и обратно.

Решение (2026-09-07): **без изменений прошивки**, только файлы веб-интерфейса.

Механизм:
- В старой версии остаются только страницы режимов (`index`, `distiller`, `bk`, `nbk`, `beer`, `cheese`)
  и настройки (решение 2026-09-07). График, программа, редактор, калибровка, brewxml, i2cstepper — только новые;
  старые страницы режимов ссылаются на них по прежним адресам. Старые файлы замораживаются как есть и живут
  в `data_raw/legacy/` → на устройстве `/legacy/*.htm.gz`, `/legacy/style.css.gz`, `/legacy/app.js.gz`. Их отдаёт общий `serveStatic("/")` (с автоподстановкой `.gz`).
- Страница настроек `setup.htm` — одна на оба интерфейса: сервер подставляет значения по шаблону только
  по адресу `/setup.htm`, копия в `/legacy/` осталась бы пустой. Старый/новый вид настроек переключается
  таблицей стилей (`legacy/style.css` против `style.css`) по тому же флагу. При желании так же поступить
  с `calibrate*.htm` и `edit.htm`.
- Файлы `/legacy/` не входят в список веб-обновления прошивки (`kWebOverrideFiles`), попадают на устройство
  только при полной заливке файловой системы; они заморожены, так что это разовая операция. Запросы `/ajax`, `/ui-bootstrap`, `/command`
  в старых страницах абсолютные, поэтому из `/legacy/` они работают без правок.
- Выбор хранится в браузере: `localStorage.samovar_ui = "legacy" | "new"`. Новые страницы при загрузке
  проверяют флаг и перенаправляют на `/legacy/<та же страница>`; старые страницы получают кнопку
  «Новый интерфейс», которая снимает флаг и ведёт на `/index.htm`. В новом интерфейсе ссылка
  «Старый интерфейс» в навигации (и в «Ещё» на мобильном).
- Принудительно: `?ui=legacy` или `?ui=new` в адресе — записывает флаг и открывает нужную версию.
  Полезно для мобильных приложений и закладок.
- Страница режима в `/legacy/` — статическая, без серверного редиректа по активному режиму, поэтому
  ссылка «Старый интерфейс» сама подставляет страницу текущего режима (режим известен из `ui-bootstrap`).

Почему не настройка в прошивке: потребовала бы поле в `SamSetup`, пункт в настройках, обработку в
`send_index_page`/`send_mode_specific_htm` и перенос `serveStatic`-страниц на `server.on`. Браузерный флаг
даёт то же самое, а разным людям на одном устройстве — свой выбор.

Флеш: копия старого UI (htm+js+css в gz) ≈ 172 КБ, итог ≈ 545 КБ из 1 МБ раздела. Остальное занимают логи
`data.csv`/`data_old.csv`: прошивка пишет лог, пока свободно больше 16 КБ, потом удаляет старый файл
(`FS.ino`, `DATA_LOG_CLEANUP_THRESHOLD_BYTES`). То есть место под историю графика сократится примерно
с 620 до 450 КБ. Принято: в `legacy/` только страницы режимов и настроек, общие страницы новые (экономия ≈ 60 КБ,
итог ≈ 485 КБ, под логи ≈ 510 КБ).
Тесты: 29 браузерных тестов рендерят `data_raw/*.htm`; после переработки они проверяют новый UI,
для `legacy/` достаточно одного дымового теста «страница открывается и опрашивает /ajax».

## План внедрения (после согласования)
1. `style.css` → новые токены и компоненты, старые классы оставить как алиасы на время миграции.
2. Partial `scheme_rect.htm` (SVG) + функция `SamovarApp.renderScheme(telemetry)` в `app.js`.
3. `index.htm` (ректификация) — новая раскладка, прогон 29 браузерных тестов и smoke.
4. `distiller.htm`, `bk.htm`, `nbk.htm` — по той же сетке, своя схема.
5. `beer.htm`, `cheese.htm` — схема котла.
6. `chart.htm`, `program.htm`, `setup.htm`, `edit.htm`, `calibrate*.htm`, `i2cstepper.htm`, `brewxml.htm` — только стили и шапка.
7. Папка `legacy/` со старым UI, флаг `samovar_ui`, ссылки-переключатели в обоих интерфейсах.
8. WordPress-плагин `samovar-mqtt-display` использует копии этих HTML — обновить `data/` плагина.

## Решения (2026-09-07)
1. Мнемосхема — живой инлайн-SVG.
2. Тема по умолчанию — системная, переключатель остаётся.
3. Отдельной кнопки «Аварийная остановка» нет: «Выключить нагрев» и есть стоп.
4. Внедрять сразу все страницы, не поэтапно.

## Итог внедрения (2026-09-07)
- Общая шапка страниц режимов — партиалы `ui_header_open.htm`/`ui_header_close.htm`, у прочих страниц —
  `ui_page_header.htm`. Датчики — `ui_sensors_top.htm`/`ui_sensors_rest.htm`, служебная строка — `ui_sys_line.htm`.
- Мнемосхемы: `scheme_rect.htm`, `scheme_dist.htm`, `scheme_bk.htm`, `scheme_nbk.htm`, `scheme_kettle.htm`

  производные величины считает `deriveView()` в `app.js`.
- Медный акцент кнопок затемнён до `#a3561a` (hover `#8a4814`): исходный `#b8641f` давал 4.3:1 с белым
  текстом, порог WCAG AA — 4.5:1. Декоративная медь схемы (`--copper`) осталась `#b8641f`/`#e08a3c`.
- На телефоне нижняя панель действий — это сама карточка «Действия» (`.sec-actions` закрепляется через
  `position: fixed`), а не дубликаты кнопок: у элементов управления один id и один обработчик.
- Тесты: базовая геометрия `setup.htm`/`chart.htm` в `test_u04_responsive_layout_browser.py` снята заново,
  пины акцента в `smoke_u03_contrast.py` обновлены, добавлен `test_legacy_ui_browser.py`
  (страницы `/legacy/` открываются, опрашивают `/ajax`, переключатель `samovar_ui` работает в обе стороны).
- Для прохождения U-03 (контраст): акцентный текст в тёмной теме — отдельный токен `--accent-text`
  (`#e08a3c`), у цветных кнопок фокус — двойное кольцо (внутреннее цвета страницы, внешнее медное),
  у прогресс-бара убран `transition: width` (геометрия светлой и тёмной тем должна совпадать точно),
  пути к `Green.png`/`alarm.mp3` в `app.js` строятся от адреса самого скрипта (`assetBase`),
  чтобы страницы работали и из подпапки (тесты).

## Отказ от старого интерфейса (2026-09-07, позже в тот же день)
Решение: старый интерфейс убран целиком. Удалены `data_raw/legacy/` (страницы режимов, их partials и `style.css`),
переключатель `localStorage.samovar_ui` / `?ui=legacy|new` и `SamovarApp.openLegacyUi()` в `app.js`,
кнопка «Старый интерфейс» в шапке, сборка `/legacy/` в `tools/build_web_assets.py` и тест
`test_legacy_ui_browser.py`. Разделы выше про механизм переключения и расход флеша на копию — история.
На устройстве после полной заливки файловой системы каталога `/legacy/` больше нет; при обновлении
только веб-файлов старые `/legacy/*.gz` остаются лежать без ссылок на них.
